"Oriented Orders" are ORD bundles that build-up a for step-by-step "ORD-NNNN.zip" output containing most of AI's the Harness and Model instructions will consume.



An Oriented Order must be object-oriented and will not fail the ORD's pattern if multiple objects are setted.



An Oriented Order may be chained along others, creating a nicknamed folder of a "DRAWING" (Glyph's core workflow). The drawing must have a folder for itself, containing its own pattern of "ORD-NNNN.zip", recognized by a built-in signature.



The Signature let other workflows accept another's ORDs, allowing the engine to chain them all for an otimized output.



Setting signatures of oriented orders may alter the base behaviour of the engine, calling for extra checks or recursive functions amidst the bundle's output. This is the main way to Glyph for a project.
