# Briefing — 2026-09-24: o Glyph em Rust, pelo caminho curto

> Para retomar no Claude Code sem reler a conversa. O trabalho é a série
> **EMS-001**, e a spec dela está em [`EMS-001/EMS-001.pgml`](EMS-001/EMS-001.pgml):
> ela decide a direção, revoga o que morreu e enfileira 14 ORDs. Não implementa
> nada.

## 1. A direção — decidida pelo Regente

> *"cara… não é só criar um app com instalador? a gente precisa focar no
> funcional […] vamos focar da seguinte maneira: um app pequeno, contido e
> limitado. serve pra substituir o Glyph de navegador? se não, vamos o
> alimentando com features pouco a pouco, até que ele supere o motor em JS"*

1. **Não é migração big-bang.** Um app Rust novo começa minúsculo e come o território do JS aos poucos. Os dois convivem o tempo que for preciso, **sem andar acoplados**.
2. **O app de navegador fica: é o MVP.** A skill continua entregando o motor JS legível.
3. **O primeiro binário lê Glyph e emite XML**, byte a byte igual ao JS. O teste é o que já existe: os 5 exemplos de `conformance/examples.json` e o oráculo das 114 fontes declaradas.
4. **O motor é um processo próprio**, por stdio ou HTTP em localhost. O visual é o app de navegador existente, apontado para o motor Rust, sem reescrever a UI.
5. **WASM sai do plano.** Com o navegador no JS, o Rust não precisa de WASM, e `wasm-bindgen` sai junto.
6. **A janela nativa vem por último.** O candidato era `wry` + `tao`, e não Tauri, Electron nem Photino. Os três desembocam no mesmo lugar com mais peso.
7. **`wry` + `tao` foram medidos antes de aceitos.** Veja §4: o resultado não é o esperado.

## 2. A correção de alvo que mais importa

O que ameaçava o MVP **não era a norma de dependência**. Era a pergunta O1, que a escada resolvia com a M11d: JS e Rust em **lockstep permanente**, com toda mudança da linguagem aterrissando duas vezes, nos dois motores, para sempre.

A direção nova resolve isso. Os dois motores deixam de andar acoplados: o Rust só precisa alcançar o JS no pedaço que está comendo, e o JS segue livre enquanto alguém o usar. A única amarra que fica é deliberada e local: enquanto o oráculo for o teste, uma feature nova entra primeiro no JS e nas stores, para o Rust ter contra o que se comparar.

## 4. `wry` + `tao`, medidos

| | crates | profundidade | linhas vendorizáveis | build limpo |
|---|---|---|---|---|
| `wry` + `tao` | 78 | 12 | 5,26 milhões | 50 s |
| `tauri`, para comparar | 236 | 16 | 7,4 milhões | 75 s |

Pelo critério do Regente, é **continente**:

- **O peso vem das camadas de API do sistema operacional:** `windows` sozinho tem 1,8 milhão de linhas, mais duas versões de `windows-sys`, mais `winapi`, mais `gtk`/`objc2` para as outras plataformas.
- **A profundidade vem do tratamento Unicode de URL.**

É melhor que o Tauri, mas não é base rasa.

O caminho sem nenhum crate: o motor abre o Edge, que já vem no Windows, em modo aplicativo (`msedge --app=http://127.0.0.1:<porta>`). A janela sai sem barra de navegador. É a `ORD-0014` da EMS-001, e só abre com o Regente aceitando a árvore ou escolhendo o outro caminho.

## 5. Os nomes, ratificados

| sentido | nome |
|---|---|
| o macro da linguagem (`[--nome=`, `[ph-x]`) | **template** |
| os formulários do app | **mould** |
| os exemplos prontos | **sample** |
| as Ordens genéricas | **Order Matrix** |
| trechos prontos do editor | **snippets** |
| o layout de renderização | **layout** |

- **Norma:** *"é melhor firmar os termos técnicos e teóricos em inglês"*, também na interface em português.
- **Grafia:** en-EU. É o lock T13 da `ORD-2026-08-30-01`, *"en-EU across the system, always"*. Por isso é `mould`, e não `mold`.
  - Medido no que está commitado: o que o motor emite está 113 a 5 em grafia britânica, e a prosa, 112 a 20.
  - *mould* e *mold* carregam os mesmos dois sentidos (a fôrma e o fungo); a escolha entre eles é só regional.
- **`modelo` na UI:** medido linha a linha. Cada ocorrência era o template ou o modelo de IA, sem terceiro uso. O que era template virou `template`, e `modelo` ficou para o modelo de IA.

## 7. Dois defeitos achados e corrigidos

- **O Tauri tinha dois números:** `ladder.toml:590` dizia 218 e o intake, 236. Os dois foram medidos, mas 218 conta só as dependências de runtime e 236 inclui as de build, que é o método do intake. Ficou 236.
- **O intake afirmava** que o limiar "≤5 e ≤20" recusava tudo o que era continente. **É falso.** O limiar admite `wasm-bindgen` (12 crates, profundidade 5), que o §9.2 classifica como continente. E admitiria `serde` no núcleo, onde a proposta escreve JSON à mão. O parágrafo agora diz isso.

## 9. Como retomar

```bash
npm run check          # JS, portões e suíte
npm run check:rust     # setas dos crates + cargo test
node scripts/test-corpus.js --export-oracle   # o oráculo em rust/target/oracle/
node scripts/crate-graph.js                   # crates, oráculos e setas
```

1. Construir o layout `.orders/EMS-###/ORD-####/`, e ensinar a série ao `--bundle` e ao plugin.
2. Emitir a spec da EMS-001 e a `ORD-0001` com o plugin (`/glyph-markup:repo-config:guidelines:orders:bundle`), que numera e empacota com o motor.
3. Abrir a `ORD-0001`: o oráculo congelado.

Fundo, se precisar: [`INTAKE-RUST-LADDER.md`](INTAKE-RUST-LADDER.md) guarda as medições (§9 dependências, §11 nomes, §12 grafia), e [`.decisions/`](../.decisions/README.md) guarda as palavras dele.
