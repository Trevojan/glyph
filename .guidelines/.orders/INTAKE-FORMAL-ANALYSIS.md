## 1. C — the burn as a normal form

Foundation for nothing else here; independent of A and B; the only one already
measured to failure, so the only one with a theorem that names the defect.

### 1.1 The burn `β`

`β : T(V) → T(A)`. On a node labelled `k ∈ K` with operand children `args`:
replace the node by `φ(k)`, with `args` prepended to the children of the
**head** of `φ(k)` — the first command node in document order (§0.3, *the
human's operand is the subject of the whole formula*). Recurse. On `A ∪ L`:
identity.

**Termination.** Let `M(t)` be the multiset `{depth(label(v)) : v ∈ t, label(v) ∈ V}`.
One expansion removes an element of value `d ≥ 1` and adds elements all of value
`< d` — every `v ∈ φ(k)` has `depth(v) < depth(k)` because `D` is acyclic and
`depth` is defined as one more than the deepest child. The multiset ordering is
well-founded (Dershowitz–Manna), so `β` terminates. Expansion steps ≤ composite
occurrences in `β(t)` ≤ `|β(t)|`.

**Size.** `|β(t)| = Σ_{v ∈ t} c(label(v))`, with `c(a) = 1` on atoms and `c(ℓ) = 1`
on literals. Hence `n ≤ |β(t)| ≤ c_max · n = 97 n`. *Measured:* a 4-command input
burned to 100 hieroglyphs; the README's "≈ 25×" is `c` averaged over real
inputs, inside the bound.

**Time.** Each node of `β(t)` is produced once; `φ(k)` is re-parsed at every occurrence (`burnList`, `parse(e.formula, …)`) — a constant factor of `|φ(k)|` per composite node, absorbed into `c`; memoising it is ~5 lines and changes nothing in the bound;
subject injection is `O(1)` (prepend to one child list). **`O(|β(t)|) = O(c·n)`**,
linear in the input with a vocabulary-dependent constant.

### 1.2 The equivalence `~` and what "normal form" claims

Let `~` be the least equivalence on `T(V)` generated by the synonymies the
notation **declares** — nothing else counts, and collapsing two spellings the
notation calls different meanings would be a defect:

| generator | source | normalised where |
|---|---|---|
| `[cr x] ~ [crit x]` | `ALIAS` | `classify()`, before `β` |
| `[CRIT x] ~ [crit x]` | lexer | before `β` |
| `[x;] ~ [x]` | §0.1 | parser, before `β` |
| `[A],[B] ~ [B],[A]` | **not a generator** — §0.1 since 3.4.7.05: *the order is part of what is said* | must not be normalised |
| `[k args] ~ φ(k)[args ↦ head]` | §0.3 | **`β` itself** |

`β` is a **normal form** for `~` iff `t₁ ~ t₂ ⇒ β(t₁) = β(t₂)`. The first three
generators are discharged before `β` runs and cannot fail it. The §0.3
generator is the content of the claim; conjunction order is not a generator
at all, and a `β` that sorted it would identify two trees `~` keeps apart.

### 1.3 The dialect theorem — where `~` and `φ` disagree

Write `φ_w(k)` for `φ(k)` as its brackets parse it, and `φ_r(k)` for the tree
§0.3's prose describes (subject into the head; comma-separated items are
**siblings** of the head). §0.3 asserts `[k args] ~ φ_r(k)[args]`. `β` computes
`φ_w(k)[args]`. Therefore:

> **`β` is a normal form for the §0.3 generator iff `φ_w(k) = φ_r(k)` for every
> `k ∈ K`.**

*Measured (`INTAKE-BURN-INVARIANCE.md` §3–§5):* `φ_r` is not a second rule;
§0.3 reads a comma inside a head's brackets as operands (its own `VRFY` gloss)
and at depth 0 as siblings — the brackets decide at every depth, so
`φ_r(k) = φ_w(k)` by definition wherever the norm does not spell `k` out. The
norm spells out one composite, `CRIT`, with the head closed; the table had it
open. That was the one measured `φ_w ≠ φ_r`; the table now carries the norm's
spelling, V5 is byte-identical to V1, and the theorem's premise holds across
the table. `β` is a normal form for the §0.3 generator.

The comma-depth audit stands as a description (9 inside, 13 at depth 0,
`CNSD` mixed), not as a defect count. The gate that follows is not comma
depth but **norm↔table equality**: every formula §0 quotes must equal
`expansions.txt`. One pass, `O(Σ|φ(k)|)`; proposed, not built.

### 1.4 Conjunction order — preserved by requirement

§0.1 in force makes `[A],[B]` and `[B],[A]` two intentions (*what is to be
done is declared before the subject*). So `canon` on `T(A)` is the identity,
`β` alone is the normal form for `~`, and the AHU sort that an earlier reading
of §0.1 would have called for is **not built and must not be**: it was
implemented once (2026-09-16), passed every variant, and was reverted because
V6 passing is V6 collapsing a distinction. `INTAKE-BURN-INVARIANCE.md` §6.

### 1.5 Operations and cost

| operation | structure | time | space | status |
|---|---|---|---|---|
| parse `φ(k)`, all `k` | 32 cached trees | `O(Σ|φ(k)|)` once | `O(Σ|φ(k)|)` | exists |
| `β(t)` | recursive substitution on `T(V)` | `O(c·n)`, `c ≤ 97` | `O(c·n)` | exists, `H-01..H-09` |
| `depth`, cycle check on `D` | DFS | `O(|V| + |E_D|) = O(307)` | `O(|V|)` | exists, `dag.js` exit 0 |
| norm↔table check (§1.3) | one pass over the formulas §0 quotes | `O(Σ|φ(k)|)` | `O(1)` | **gate to add** |
| `canon(β(t))` (§1.4) | identity | `O(1)` | — | `β` is already canonical; a sort would be a defect |

| | invariant | holds? | gate |
|---|---|---|---|
| `I_C1` | `D` is acyclic | ✓ *measured* | `dag.js`, exit ≠ 0 on cycle |
| `I_C2` | every `v ∈ φ(k)` is in `V`; every `k` has `φ(k)` | ✓ *measured* | `dag.js` 0 undefined; build refuses |

## 2. B — the declared edge graph between Orders

Precedes A: it is the smallest instance of the reference primitive A generalises
(§4). Independent of C: relations are read from the AST, before any expansion.

### 2.1 Objects

`G_B = (O, E_B)`, `E_B ⊆ O × R × O`. An edge `(o, r, o')` is **declared** in
`o`'s source as a relation command with a `REF` child naming `o'`:
`[ovr[ref'ORD-0003']]`. Extraction is a walk of `o`'s AST selecting nodes with
`canonical ∈ R` and a `REF` child whose literal matches the Order-ID pattern.

Partition `R` by what the edge does to the target's **activity**:

| kind | reads | effect on `o'` | in the replacement subgraph `E_B^↓`? |
|---|---|---|---|
| `OVR` | `o` overrides `o'` | inactive on the overlap | yes |
| `INSTOF` | `o` stands instead of `o'` | inactive | yes |
| `DEPR` | `o` deprecates `o'` | inactive | yes |
| `DRVF` | `o` derives from `o'` | still active; `o` depends on it | no |
| `SEEAL` | related | none | no |

`active(O) = { o ∈ O : ∄ (o', r, o) ∈ E_B^↓ }`.

### 2.2 Why the edge is declared, not inferred — the correct statement

The external source said inferred contradiction is *undecidable, by reduction to
program equivalence*. **That is not true of Glyph.** *Measured:* `[logic]` has
`let`, a guarded rule `? expr -> expr`, and arithmetic — no loop, no recursion,
no function definition. An Order describes; nothing executes; every construct
is decidable, and a `[logic]` block evaluates in time linear in its length. The
reduction to program equivalence does not apply.

The true obstacle is earlier and does not need undecidability:

1. **Ill-posed before it is hard.** "Does `[mand X]` in `o₁` contradict
   `[dont X]` in `o₂`?" needs a semantics for *the same `X` in two Orders*, and
   the vocabulary has none — no cross-Order scope, no name resolution beyond
   `binds`/`ref` inside one document. Without it the question has no truth
   value. This is the point at which `checkRules` run across two trees produces
   false positives, and it is the point `INTAKE-ORDER-COHERENCE.md` §6 named.
2. **Hard once posed.** Give each Order a propositional reading of its
   constraints (`mand X ↦ X`, `dont X ↦ ¬X`, `alw`/`nev` as quantifier-free
   literals, …). "No world satisfies both" is unsatisfiability of a
   conjunction — **coNP-complete** in the size of the two Orders. Not
   undecidable; not cheap.
3. **Declared is linear.** Every operation below is `O(|O| + |E_B|)` on a
   graph *measured* at one node and zero edges, designed for tens.

So the argument is not "inference is impossible"; it is "inference is ill-posed
until a scope semantics exists, coNP-hard after, and the declared graph is
linear and already how the repository treats composition." Same conclusion,
sound premise.

### 2.3 Operations and cost

| operation | structure | time | status |
|---|---|---|---|
| extract `E_B(o)` from one Order | AST walk | `O(n)` | not built; same shape as `binds`/`ref` extraction |
| resolve: `(o, r, o') ∈ E_B ⇒ o' ∈ O` | hash set of Order IDs | `O(1)` per edge, `O(|E_B|)` total | not built |
| cycle check on `E_B^↓` | DFS | `O(|O| + |E_B^↓|)` | not built; **`dag.js`'s algorithm on a second graph** |
| required-field gate at `--bundle` | `|E_B(o)| ≥ 1 ∨ root(o)` | `O(1)` after extraction | not built |
| `active(O)` | in-degree zero in `E_B^↓` | `O(|O| + |E_B^↓|)` | not built |
| `--check`: manifest `relates[]` equals extraction | rebuild in memory, compare | `O(Σ n_o)` | not built; the `build-*.js --check` pattern |

### 2.4 Invariants

| | invariant | holds? | gate |
|---|---|---|---|
| `I_B1` | one ID scheme, one home: `id : O → ORD-####` injective, all under one destination | **✗** *measured* — two schemes, two homes | the Regent's decision (§3 of B) |
| `I_B2` | every edge resolves: `(o, r, o') ∈ E_B ⇒ o' ∈ O` | vacuous today | `--bundle` refuses |
| `I_B3` | `E_B^↓` is acyclic — no Order replaces an Order that replaces it | vacuous today | DFS, `--bundle` refuses |
| `I_B4` | `relates` is **required**: `|E_B(o)| ≥ 1 ∨ root(o)` — absence is `fix`, the one slot where empty blocks | vacuous today | `--bundle` refuses |
| `I_B5` | `relates[]` in the manifest is a function of the AST, never hand-written | vacuous today | `--check` |

`I_B1` is the precondition of the other four and is not an engine property.

### 2.5 Defeasible logic — the vocabulary, and its honest reach

The relation kinds are a **superiority relation** in the sense of defeasible
logic (Nute): `(o, OVR, o')` reads `o > o'` — where the two conflict, `o`
defeats `o'`. `I_B3` is exactly the requirement that `>` be acyclic, which
defeasible logic also imposes. And the strongest known result is favourable:
**propositional defeasible logic with a superiority relation is decidable in
time linear in the theory** (Maher, *Propositional Defeasible Logic has Linear
Complexity*, TPLP 2001).

What that buys, and what it does not: the **graph** — which Orders are active,
which defeat which — is linear today, with no logic at all. The **content** —
"given the active Orders and their precedence, what does the corpus conclude
about `X`?" — would be linear *if* the Orders were propositionalised, and
propositionalising is the scope semantics §2.2 says does not exist. So
defeasible logic names what `relates[]` already is, and gives a guarantee that
would hold at the next step; it is not a mechanism to build now. AGM revision
postulates fit less well: they presuppose belief sets closed under consequence,
and an Order corpus is not closed under anything.

## 3. A — reference resolution over a document forest

Last, by discipline: it generalises B (§4) and is justified only by a
round-trip baseline that does not yet exist (`INTAKE-VIRTUAL-PATH.md` §8).

### 3.1 Objects

`H = ⊎_{d ∈ 𝒟} H(d)`, the heading forest: each `H(d)` a rooted ordered tree
whose nodes are headings with a level; a **section** is the text from a heading
to the next heading of level ≤ its own. *Measured:* `h = 421` nodes over 311 KB.

A reference `ρ = (d, σ)`: a document and a selector. Resolution
`res(ρ) ∈ [s, e) ∪ {⊥}` — the byte range of the section, or nothing.
Fingerprint `fp(ρ) = hash(content(res(ρ)))`. The resolution record the contract
stores is `{ρ, kind, granularity, fp, resolvedAt, engine}` (`INTAKE-VIRTUAL-PATH.md` §15).

### 3.2 Operations and cost

| operation | structure | time | notes |
|---|---|---|---|
| build `H(d)` | one pass, stack of open headings | `O(|d|)` | zero dependencies |
| build `H` | all documents | `O(Σ|d|) = O(311 KB)` | **milliseconds** |
| resolve `ρ` by heading path | `H(d)` indexed by path string | `O(|σ|)` hash, or `O(depth)` walk | — |
| `fp(ρ)` | hash of the section | `O(|section|)` | built-in `crypto` |
| staleness check | recompute `fp`, compare | `O(|section|)` | the contract's `ask` |
| **full rebuild** of the mini-repo | rebuild `H`, resolve all, fingerprint all | `O(Σ|d| + Σ_ρ|section(ρ)|)` | **one more `SOURCES` entry under the existing `--check`** |

### 3.3 Rebuild against incremental — the crossover

Gepeto's architecture (`D → AST → order → offsets`, order-maintenance, ropes,
event-driven update) exists to avoid the full rebuild. Its per-edit cost is
`I = O(k log N)` for `k` affected nodes, plus a fixed persistence cost `P` for
loading and writing the index. The full rebuild costs `R(N) = O(N)`.
Incremental wins only when `R(N) > I + P`.

*Estimate:* `R(311 KB)` is one file-system read of the corpus and one pass —
single-digit milliseconds in Node. `P` is at least one index read and one
write — the same order. `I` is microseconds. So `R ≈ P`, and incrementality
buys nothing until `R(N) ≫ P`, i.e. until the corpus is on the order of
**10²–10³ × the current size**. That is the formal content of "over-engineered
by three orders of magnitude" (`INTAKE-VIRTUAL-PATH.md` §6), and it is why the
recompute trigger is the commit and the gate is `--check` (§4 there): at this
size the whole-rebuild *is* the efficient algorithm.

### 3.4 Euler tour — where it applies, and the volume that would justify it

On `H(d)`, assign `tin`/`tout` in preorder. Then, in `O(1)` each:
`inside(s, t) ⟺ tin(t) ≤ tin(s) ∧ tout(s) ≤ tout(t)`;
`above(s) = { u : tin(u) < tin(s) }`; `subtree(s) = { u : tin(s) ≤ tin(u) ≤ tout(s) }`.
Preprocessing `O(h)`, one pass, ten lines. Correct.

It pays when structural queries per rebuild ≫ `h`. *Measured:* rebuild is per
commit; Cláudio's cost model puts references per session at ~10; `h = 421`.
Queries per rebuild are two orders below the point where `O(1)` beats a walk of
`O(depth ≤ 6)`. Recorded so it is not re-proposed as new; not built, because no
measured path asks for it. It does not apply to `atomsOf`/`β`, which expand a
DAG, not a tree.

### 3.5 Order maintenance — why the heading path is the stable ID here

Dietz–Sleator gives `O(1)` amortised insert/delete/`before(x, y)` on a sequence
under edits, so a node keeps an identity while its ordinal position changes. It
answers: *the document was edited under me; is this still the same node, and
where is it now?*

At this scale the question is answered without it. The rebuild is `O(N)` and
cheap (§3.3), so no index survives an edit — it is remade. Identity across the
remake is the **heading path** (a string), which is stable exactly as long as
the heading is not renamed. When it *is* renamed, order maintenance would not
help either: the node's content moved under a new name, and only the
**fingerprint** detects that (`fp` stored ≠ `fp` recomputed → `ask` → re-resolve
by selector → report the move). *Measured (M2):* 68% of edits touch under a
fifth of a file, so the path survives most edits; the 24% wholesale rewrites
are precisely the case where no structure survives and the fingerprint is the
only honest signal. Order maintenance enters only past the §3.3 crossover.

| | invariant | gate |
|---|---|---|

| `I_A2` | `fp` stored = `fp` recomputed at consumption, else `<needs ref>` at `ask` — never an empty slice | the failure contract |

## 4. The shared primitive — `A ⊇ B`

A **reference** is `(source, target, kind, granularity)`, declared in Glyph,
resolved at emission by the CLI, recorded in the manifest, checked by
`--check`. B is the instance `kind = order, granularity = whole`; A is
`kind = slice, granularity ∈ {file, section, node}`. The resolution record has
a `granularity` field for exactly this reason.

| | B | A |
|---|---|---|
| targets | `O`, tens | `H`, hundreds of sections |
| resolution | hash lookup, `O(1)` | path lookup in `H(d)`, `O(|σ|)` |
| failure | `fix` — the Order must say where it stands | `ask` — the slice may have aged |
| cycle check | required, on `E_B^↓` | not applicable (slices do not replace slices) |
| fingerprint | optional — an Order ID is the identity | required — content is the identity |

`I_A1 ≡ I_B2`, `I_A5 ≡ I_B5`. Proving the mechanism on B's ten nodes before A's
four hundred sections is the order of work, and B stands on its own if A never
happens.
